# KEAM4U

KEAM4U is a full-stack learning platform for practicing Kerala Engineering Architecture Medical (KEAM) previous-year questions. Students can browse questions by subject, year, and topic; attempt questions with a timer; track completed questions; and request step-by-step explanations generated by Google Gemini.

The project is organized as two applications:

- `frontend/` - React 19 application built with React Router 7, Vite, and Tailwind CSS.
- `backend/` - Express 4 + TypeScript API using MongoDB, Redis, Zod, Winston, and Swagger.

## Features

- Subject, year, and topic-based KEAM question browsing
- Paginated and sortable question APIs
- Timed question attempts with answer selection and instant feedback
- Local progress persistence for attempts and completed questions
- AI-generated, structured explanations using the Google Gemini API
- Report form for submitting question issues by email
- MongoDB persistence through Mongoose
- Redis caching for frequently accessed topic and question lookups
- Request logging, centralized error handling, and runtime environment validation
- Swagger/OpenAPI documentation
- Dockerfiles and Docker Compose configurations for development and production
- Responsive React Router interface for home, practice, question, sign-in, sign-up, and dashboard flows

## Architecture

```text
React Router frontend
        │
        │ HTTP / JSON
        ▼
Express API (/api/v1)
        │
        ├── Question controller → service → repository → MongoDB
        ├── Redis cache for repeated lookups
        └── Report endpoint → Nodemailer / Gmail SMTP
```

The frontend requests question data from the backend and calls Gemini after a question is submitted to generate an explanation. Attempt state and completed-question progress are stored in browser `localStorage`.

## Configuration

### Backend

Create `backend/.env` with:

```env
PORT=5000
DB_URL=mongodb://localhost:27017/keam4u
DB_USERNAME=
DB_PASSWORD=
REDIS_URL=localhost
REDIS_PORT=6379
REDIS_PASSWORD=
REPORT_EMAIL=
REPORT_EMAIL_PASSWORD=
NODE_ENV=development
LOG_LEVEL=info
```

The exact database and Redis values depend on the local or hosted services being used. The backend validates required environment variables during startup and exits when configuration is invalid.

### Frontend

Create `frontend/.env` with:

```env
VITE_BASE_URL=http://localhost:5000/api/v1
VITE_API_BASE_URL=http://localhost:5000
VITE_GEMINI_KEY=your-gemini-api-key
```

Do not commit either `.env` file or API keys. The Gemini key is used by the browser for explanation requests, so production deployments should use an appropriate key restriction or move the integration behind a server-side endpoint.

## Local Development

### Start the backend

```bash
cd backend
npm install
npm run dev
```

The API listens on `http://localhost:5000` by default.

### Start the frontend

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

The frontend is served by React Router's development server, normally at `http://localhost:5173`.

## API Overview

Base API path: `/api/v1`

### Health

```http
GET /health
```

### Questions

```http
GET /api/v1/questions
GET /api/v1/questions/:id
GET /api/v1/questions/year?year=2025
GET /api/v1/questions/topic?topic=physics
GET /api/v1/questions/:topic/q?year=2025
GET /api/v1/questions/:subject/year
GET /api/v1/questions/:subject/:year/topic
GET /api/v1/questions/:subject/:topic?year=2025
```

Question list endpoints support pagination and sorting query parameters where applicable.

### Reports

```http
POST /api/v1/report
```

Example request:

```json
{
  "questionId": "question-id",
  "question": "Question text",
  "issue": "Describe the issue"
}
```
